# NVDA 手测清单（A11Y-11 / GUI-SC3）

> 这份清单交给**人**跑。自动化能断言的是 AX 树里的 role/name/state 结构（见 `packages/desktop/test/e2e/accessibility-tree.spec.ts`），播报质量只能耳朵判断。跑完把结果回写到 `docs/PROJECT_GUIDE.md` §14（或 §11 的审计记录），不要只写"没问题"：每条都要写**实际听到什么**，与下一列的期望对照。

## 0. 环境与准备

1. Windows 装 [NVDA](https://www.nvaccess.org/)（免费），启动后确认语音能读屏。
2. 建议先把 NVDA 语速调到能听清的档位，关闭"读打字字符"以外的额外提示（`NVDA+Ctrl+S` 打开语音设置），避免把回声当成缺陷。
3. 用 `pnpm dev` 或已构建的 `colamd` 启动应用，打开一个含多级标题、列表、链接、代码块的 Markdown 文件；侧栏显示项目树（`文件` 标签）。
4. 应用已在主进程 `ready` 时显式 `app.setAccessibilitySupportEnabled(true)`，不需要额外开关；若 NVDA 读不到任何东西，先确认应用是这次构建（旧构建没有这一步）。

## 1. 编辑器本体（contenteditable 富文本）

| #   | 操作                                           | 期望播报                                                                  |
| --- | ---------------------------------------------- | ------------------------------------------------------------------------- |
| 1.1 | 打开文档后按 `NVDA+↓` 逐行浏览                 | 标题被读成"标题 1 / heading level 1"之类的**标题级**，而不是"编辑框 空白" |
| 1.2 | 在正文段落上按 `NVDA+↓`                        | 读出段落文本；行内粗体/斜体至少读出文本内容，不要求念出格式               |
| 1.3 | 焦点放回正文，输入几个字符                     | 读打字回显；不出现"未知"或整块重读                                        |
| 1.4 | 用 `Ctrl+Home` / `Ctrl+End` 移动               | 光标到达首/末块时语音有对应反馈，不卡死                                   |
| 1.5 | 进入源码模式（状态栏"源码模式"按钮，键盘可达） | 读成"多行编辑框"之类，能逐行读代码文本                                    |

## 2. 侧栏文件树（SC-2 的语义）

| #   | 操作                     | 期望播报                                                     |
| --- | ------------------------ | ------------------------------------------------------------ |
| 2.1 | `Tab` 进入侧栏，落在树上 | 读"<项目名> 树 / tree"，整棵树只占**一个** Tab 停点          |
| 2.2 | 按 `↓` / `↑`             | 每行读"名称 + 层级 + 展开/折叠 + 选中"；不读成一串无名的"项" |
| 2.3 | 在文件夹上按 `→` / `←`   | 展开读"已展开"，收起读"已折叠"；`←` 在子项上回到父文件夹     |
| 2.4 | 在文件上按 `Enter`       | 打开文档；当前文档行被读成"当前"（`aria-current`）           |
| 2.5 | 在行上按 `F2` / `Delete` | 进入重命名输入 / 弹出删除确认；对话框本身要能读（见 §7）     |

## 3. 窗口内菜单栏（SC-1）

| #   | 操作                              | 期望播报                                                          |
| --- | --------------------------------- | ----------------------------------------------------------------- |
| 3.1 | `Tab` 到菜单栏，`←` / `→`         | 读"菜单栏 / menubar"，逐项读"文件 菜单项"等；不跳进下拉           |
| 3.2 | 顶层项按 `Enter` / 空格           | 读"已展开"，焦点进入第一行                                        |
| 3.3 | 下拉内 `↓` / `↑` / `Home` / `End` | 逐行读名称；分隔线被跳过；带子菜单的行读"有子菜单，已折叠/已展开" |
| 3.4 | 勾选类行按 `Enter`                | 读"已勾选 / 未勾选"（`aria-checked`），不是只读一个 `✓` 字符      |
| 3.5 | 禁用行                            | 读"不可用"（`aria-disabled`），按键不触发动作                     |
| 3.6 | `Esc`                             | 读"菜单已关闭"，焦点回到顶层项                                    |

## 4. 侧栏宽度拖拽条（SC-4）

| #   | 操作                  | 期望播报                                                                  |
| --- | --------------------- | ------------------------------------------------------------------------- |
| 4.1 | 从侧栏 `Tab` 到宽度条 | 读"侧栏宽度 / Sidebar width，分隔符 / separator"，并读出当前值（如"280"） |
| 4.2 | `→` / `←`             | 值按 16 递增/递减，语音随之更新；`Shift+→` 按 64 变                       |
| 4.3 | 缩到最小              | 停在 220，不继续变小、不读越界值                                          |

## 5. 搜索栏

| #   | 操作                       | 期望播报                                                    |
| --- | -------------------------- | ----------------------------------------------------------- |
| 5.1 | `Ctrl+F` 打开搜索          | 焦点落在输入框，读"查找"                                    |
| 5.2 | 输入一个有多个匹配的关键词 | 结果计数通过 live region 读出（如"3 / 10"），不需要手动刷新 |
| 5.3 | `Enter` / `Shift+Enter`    | 上/下一个匹配，计数同步变化                                 |

## 6. 通知与状态栏

| #   | 操作                              | 期望播报                                |
| --- | --------------------------------- | --------------------------------------- |
| 6.1 | 保存一个文件                      | 成功通知被播报（role=status），不是静默 |
| 6.2 | 制造一次保存失败（只读目录/权限） | 错误通知被播报                          |
| 6.3 | 状态栏字数切到"字符/段落"         | 读出新口径，不是永远"字数"              |

## 7. 未保存对话框

| #   | 操作                 | 期望播报                                                                                                                                    |
| --- | -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| 7.1 | 改脏一个标签后关窗口 | 对话框标题与正文读出**具体文件名**；文件名超过 5 个时，列表末尾读出"等 N 个"（≤5 个时不单独报总数——文件名本身就是完整清单，见 #122 的处置） |
| 7.2 | 初始焦点             | 落在第一个按钮（安全默认），`Tab` 不会跑出对话框                                                                                            |
| 7.3 | 三个按钮             | 读"保存 / 不保存 / 取消"等完整名称                                                                                                          |
| 7.4 | `Esc` / 关闭         | 焦点回到原来的编辑器                                                                                                                        |

## 8. 快速打开与命令面板

| #   | 操作      | 期望播报                                    |
| --- | --------- | ------------------------------------------- |
| 8.1 | `Ctrl+P`  | 读面板与输入框名称，空库时不静默失败        |
| 8.2 | `↓` / `↑` | 每行读"选项 + 名称"；不是只改高亮、语音不动 |
| 8.3 | `Enter`   | 执行并关闭，焦点回到编辑器                  |

## 9. 回写方式

- 每条记录三列：**操作 / 期望听到 / 实际听到**；不符的写明"听不清/没读出/读错内容"，并附上 NVDA 版本、应用版本、语言（`zh-CN` 或 `en`）。
- 结果写进 `docs/PROJECT_GUIDE.md` §14（或 §11 的稳定期审计记录），同时在本清单末尾留一行日期与结论。
- 若整棵树都读不到，先确认 `app.isAccessibilitySupportEnabled()` 为真（e2e 的 `accessibility-tree.spec.ts` 已断言这一点），再检查 NVDA 是否在应用启动前就已运行。
